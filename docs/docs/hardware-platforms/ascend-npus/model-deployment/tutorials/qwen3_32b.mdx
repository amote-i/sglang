## Introduction

Qwen3-32B is a dense model in the Qwen3 series developed by Alibaba, featuring 32B parameters with Grouped-Query
Attention (GQA) and up to 128k (131k with YaRN) context length. It delivers significant improvements in instruction following, logical
reasoning, text comprehension, mathematics, science, coding, and tool usage. The model supports EAGLE3 speculative
decoding for accelerated inference and supports both standard and thinking/reasoning modes.

This document demonstrates the deployment of Qwen3-32B on Ascend NPUs using SGLang, including single-node PD mixed mode,
feature configuration, and performance optimization.

This document is validated and written based on **SGLang v0.5.18**. The current model (Qwen3-32B) is fully supported in
this version. It is recommended to use exactly v0.5.18 (the `v0.5.18-cann9.0.0-a3` image); later versions are not
covered by this document and may introduce breaking changes.

## Supported features

| Feature                       | Example usage                                                                                 |
|-------------------------------|-----------------------------------------------------------------------------------------------|
| Tensor Parallelism            | `--tp-size 4`                                                                                 |
| Quantization                  | `--quantization modelslim`                                                                    |
| NPU Graph                     | enabled by default; disable with `--disable-decode-cuda-graph --disable-prefill-cuda-graph`;<br/>control range via `--cuda-graph-bs-decode` or `--cuda-graph-max-bs-decode`; e.g., `--cuda-graph-bs-decode 1 4 8 16` |
| Speculative Decoding          | `--speculative-algorithm EAGLE3 \`<br/>`--speculative-draft-model-path /path/to/draft-model-weights \`<br/>`--speculative-num-steps 3 \`<br/>`--speculative-eagle-topk 1 \`<br/>`--speculative-num-draft-tokens 4 \`<br/>`--speculative-draft-model-quantization unquant` |
| Overlap Schedule              | `export SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1`                                                  |

[Parameter Reference](/docs/hardware-platforms/ascend-npus/optimization/parameter_tuning#parameter-reference); for

### Model weights

Before downloading model weights, check the model size to reserve enough disk space.
For multi-node deployment, download the weights to a shared directory accessible to all nodes.

- [Qwen3-32B](https://www.modelscope.cn/models/Qwen/Qwen3-32B) (BF16, 65.54GB)
- [Qwen3-32B-W8A8](https://www.modelscope.cn/models/vllm-ascend/Qwen3-32B-W8A8) (W8A8 quantized version, 42.77GB)
- [Eagle3-Qwen3-32B-zh](https://www.modelscope.cn/models/Zjcxy-SmartAI/Eagle3-Qwen3-32B-zh) (EAGLE3 draft model for speculative decoding)

<Info>
The BF16 variant (65.54GB) can be deployed on 2 × 64GB of device memory (`--tp-size 2`), which corresponds to 1 card (2 dies) on A3 Series.

The W8A8 variant (42.77GB) fits within a single die.
</Info>

This is the minimum recommended configuration. For optimized configurations,
see [Best practices](#best-practices), which may require additional cards or nodes.

For the hardware specifications (memory per die and dies per card),
see [Ascend NPU Reference — Hardware](/docs/hardware-platforms/ascend-npus/reference/glossary#hardware).

## Installation

<Warning>
Ensure sufficient disk space before pulling images. The Docker image requires at least **30GB** of free space.
</Warning>

The dependencies required for the NPU runtime environment have been integrated into a Docker image and uploaded to the
online platform. You can directly pull it.

The following command is based on the stable release tag `v0.5.18-cann9.0.0-a3`.
For details, see [Docker image versions](/docs/hardware-platforms/ascend-npus/faq#8-docker-image-versions-stable-release-vs-daily-build).

The command requires
[Ascend Docker Runtime](/docs/hardware-platforms/ascend-npus/getting-started/installation#install-ascend-docker-runtime)
on the host; it selects all NPUs of the node with `ASCEND_VISIBLE_DEVICES`.

{/* NOTE(agent): The image version and scripts in this file are frozen (validated best practice). Skip this file in batch image-version updates and when deprecating or renaming parameters/flags. */}
```bash Command
# ============================================================
# Before running, update the following variables or use default values:
#   NAME: container name
# ============================================================

NAME=sglang-qwen3-32b

# pull image
docker pull quay.io/ascend/sglang:v0.5.18-cann9.0.0-a3

# create container
docker run -itd --shm-size=16g --name "$NAME" \
--privileged=true --net=host \
-e ASCEND_VISIBLE_DEVICES=0-15 \
-v /etc/ascend_install.info:/etc/ascend_install.info \
-v /usr/local/sbin:/usr/local/sbin \
-v /usr/local/Ascend/driver:/usr/local/Ascend/driver \
-v /usr/local/Ascend/firmware:/usr/local/Ascend/firmware \
--entrypoint=bash \
quay.io/ascend/sglang:v0.5.18-cann9.0.0-a3

# enter container
docker exec -it "$NAME" bash
```

<Tip>
- If the model weights have already been downloaded to a shared directory, use `-v` to mount the model path into the
  container, for example: `-v /path/to/models:/models`.
</Tip>

## Online service deployment

### Single-node online deployment

Single-node deployment completes both prefill and decode within the same node (PD mixed mode), suitable for scenarios
with limited hardware resources. Use the `Qwen/Qwen3-32B` checkpoint on one A3 Series card (2 dies), with TP2.

```shell
# ============================================================
# Before running, update the following variables:
#   MODEL_PATH: path to the model weights directory
#   DRAFT_MODEL_PATH: path to the draft model weights directory
# ============================================================

MODEL_PATH=/path/to/Qwen3-32B
DRAFT_MODEL_PATH=/path/to/Eagle3-Qwen3-32B-zh

source /usr/local/Ascend/ascend-toolkit/set_env.sh
source /usr/local/Ascend/nnal/atb/set_env.sh

export SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1

python3 -m sglang.launch_server \
    --model-path $MODEL_PATH \
    --host 127.0.0.1 --port 6688 \
    --trust-remote-code \
    --attention-backend ascend \
    --device npu \
    --tp-size 2 \
    --dtype bfloat16 \
    --mem-fraction-static 0.85 \
    --speculative-algorithm EAGLE3 \
    --speculative-draft-model-path $DRAFT_MODEL_PATH \
    --speculative-num-steps 4 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 5 \
    --speculative-draft-model-quantization unquant \
    --reasoning-parser qwen3 \
    --tool-call-parser qwen
```

For the complete benchmark data and additional single-node configurations, see
[Qwen3-32B Best Practice — PD Mixed On A3 Series](/docs/hardware-platforms/ascend-npus/model-deployment/best-practices/qwen3_32b#single-node-pd-mixed).

## Functional verification

The launch command runs the server in the foreground. Loading the weights and capturing graphs takes a few minutes.
Once the logs print `The server is fired up and ready to roll!`, open another terminal (or another
`docker exec -it ${NAME} bash` session) and invoke the model:

```shell
curl http://127.0.0.1:6688/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{"role": "user", "content": "What is the capital of France?"}]
  }'
```

Expected result: an HTTP 200 response with the generated text containing "Paris".

<Tip>
The commands on this page assume the default service address `127.0.0.1:6688` from the launch command above. If you
started the service with a different `--host` or `--port`, replace the address in these commands accordingly.
</Tip>

For more testing examples (Health Check, Generate, Chat Completions, and port usage guidance),
see [Testing the Service](/docs/hardware-platforms/ascend-npus/getting-started/installation#testing-the-service).

## Accuracy evaluation

A quick accuracy check on GSM8K with `sgl-eval`:

```shell
# Install sgl-eval in an isolated venv (not the server environment)
python3 -m venv .venv-sgl-eval
source .venv-sgl-eval/bin/activate
pip install sgl-eval==0.1.3

sgl-eval run gsm8k \
  --base-url http://127.0.0.1:6688/v1 \
  --num-examples 10 --max-tokens 16384
```

<Note>
This is a 10-example connectivity check, not a comparable accuracy score. `sgl-eval` applies its own generation defaults and GSM8K runs with thinking off by default.
For reasoning models, pass the model's thinking setting explicitly (`--thinking` for DeepSeek/Kimi style, `--chat-template-kwarg enable_thinking=true` for Qwen3/GLM style); skip it when the model forces thinking on. See the Accuracy Evaluation on Ascend NPU page for details.
</Note>

For accuracy evaluation methods and datasets, see [Accuracy Evaluation on Ascend NPU](/docs/hardware-platforms/ascend-npus/evaluation/accuracy_evaluation).

## Performance

A quick performance benchmark with random input/output lengths:

```shell
python -m sglang.benchmark.serving \
    --dataset-name random \
    --backend sglang \
    --host 127.0.0.1 \
    --port 6688 \
    --max-concurrency 64 \
    --num-prompts 64 \
    --random-input-len 1000 \
    --random-output-len 100 \
    --random-range-ratio 1 \
    --seed 1
```

<Note>
`--backend sglang` targets `/generate`, so this measures raw text throughput without the chat template or reasoning parser. To benchmark the `/v1/chat/completions` path verified above, use `--backend sglang-oai-chat`.
</Note>

For performance data and benchmark commands, see [Performance Testing on Ascend NPU](/docs/hardware-platforms/ascend-npus/evaluation/performance_testing).
