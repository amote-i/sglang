This guide helps you tune SGLang deployments on Ascend NPU. Use it in one of three ways:

- **Tune for a goal**: start with [How to Tune](#how-to-tune), identify your goal in [Tuning by Goal](#tuning-by-goal), then follow a [scenario checklist](#scenario-checklists).
- **Look up a parameter**: go directly to the relevant section of the [Parameter Reference](#parameter-reference) from the table of contents.
- **Check a combination**: see [Feature Compatibility](#feature-compatibility) before enabling several features together.

Reference values are drawn from the published best-practice configurations — primarily the
[DeepSeek-V3.2 PD disaggregation configuration](/docs/hardware-platforms/ascend-npus/model-deployment/best-practices/deepseek_v3_2#pd-disaggregation) —
with the source model noted where it differs. For complete deployment scripts and benchmark results, see the
[DeepSeek R1 best practice](/docs/hardware-platforms/ascend-npus/model-deployment/best-practices/deepseek_r1) page.

<Info>
  These are **deltas on a working deployment**. Environment setup and the validated software stack are covered in
  [Installation](/docs/hardware-platforms/ascend-npus/getting-started/installation). The reference values were
  validated on A2/A3 with the image named on each best-practice page (DeepSeek V3.2: `v0.5.18-cann9.0.0-a3`);
  check the [Feature Support Matrix](/docs/hardware-platforms/ascend-npus/reference/support_features) for 950PR/DT
  differences before copying a value to another device.
</Info>

<Note>
  Parameters fall into two categories:

  - **Required configurations** (marked with `[Required]`): must be set correctly for the target deployment scenario (e.g., multi-node communication, PD disaggregation). Incorrect values cause deployment failures or incorrect behavior.
  - **Performance optimizations**: improve throughput, latency, or memory efficiency. The optimal value depends on your model, hardware, and workload — treat the reference values as starting points, not defaults.
</Note>

## How to Tune

1. **Define the goal and measure a baseline.** Choose the target metric — TTFT (time to first token), TPOT (time per output token), throughput (tokens/s), or memory headroom — and benchmark the current configuration before changing anything. [Performance Testing](/docs/hardware-platforms/ascend-npus/evaluation/performance_testing) shows the command and how to read Mean TTFT/Mean TPOT; the best-practice pages also provide per-model `python -m sglang.benchmark.serving` commands. Record the seed, input/output lengths, and concurrency with every run. For a kernel-level view, use [Profiling](/docs/hardware-platforms/ascend-npus/optimization/profiling).
2. **Tune top-down.** Determine the deployment topology first (parallelism, PD disaggregation). Then choose the load-shape parameters that consume memory — `--chunked-prefill-size`, `--cuda-graph-max-bs-decode`, and speculative decoding — and only then size `--mem-fraction-static`, because activation and graph buffers are inputs to the memory budget. Communication settings (interfaces, buffers) and the remaining kernel switches are tuned last. Higher levels bound what lower levels can achieve — graph-level tuning cannot compensate for an incorrect TP/EP split.
3. **Change one parameter at a time, re-measure, and retain the better configuration.** Record every configuration you benchmark so results stay comparable.
4. **Verify before keeping it.** After quantization or speculative decoding, run the [accuracy evaluation](/docs/hardware-platforms/ascend-npus/evaluation/accuracy_evaluation); after any change, re-run the same benchmark and compare the metrics. Keep the previous configuration so you can roll back.

## Tuning by Goal

Where to start for common tuning goals. Parameters are ordered by expected impact; each carries its own cost.

### Lower decode latency (TPOT)

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [Speculative decoding](#speculative-decoding) | Verifies several draft tokens in one target forward | Draft compute; acceptance-rate dependent — re-run the [accuracy evaluation](/docs/hardware-platforms/ascend-npus/evaluation/accuracy_evaluation) |
| [`--cuda-graph-max-bs-decode`](#decode-tuning) | Removes kernel-launch overhead | Capture time and memory; must be at least, and a multiple of, `attn_tp_size` |
| [`--attn-dp-size`](#parallelism) | More independent decode instances | Attention must not be the bottleneck; must divide TP |

If further reduction is needed: `SGLANG_SCHEDULER_SKIP_ALL_GATHER=1` — only with balanced DP load.

### Higher throughput

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [`--attn-dp-size`](#parallelism) | More independent decode instances | Per-request latency can rise; must divide TP |
| [`--max-running-requests`](#prefill-tuning) (decode uses 32–1024) | More concurrent requests per node | Per-request latency rises; the KV pool must fit them |
| [`--tokenizer-worker-num`](#throughput-tuning) | Keeps tokenization off the critical path | Some features require `1` (native gRPC, elastic EP) |

Also consider: [`--ep-size`](#parallelism) (distribute experts across cards), [`--mem-fraction-static`](#memory-and-device-configuration) (more KV cache — monitor for out-of-memory (OOM) errors).

### Lower time to first token (TTFT)

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [`--chunked-prefill-size`](#prefill-tuning) on mixed workloads | Short requests are not delayed behind a single long prefill | A small prefill overhead per chunk |
| Prefix caching (leave [`--disable-radix-cache`](#prefill-tuning) unset) | Reuses KV of shared prompt prefixes | Radix-tree memory; no benefit without shared prefixes |
| [`--attn-cp-size`](#parallelism) for long inputs | Splits one long sequence across devices | More inter-device communication; requires the prefill CP flags |

### Resolve OOM errors

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| Lower [`--mem-fraction-static`](#memory-and-device-configuration) | Leaves room for activations and graph buffers | Less KV cache — fewer concurrent requests |
| [`--quantization modelslim`](#quantization) | W8/W4 checkpoints reduce weight memory by approximately 50%/75% | A small accuracy loss — re-run the [accuracy evaluation](/docs/hardware-platforms/ascend-npus/evaluation/accuracy_evaluation) |

Also consider: `PYTORCH_NPU_ALLOC_CONF=expandable_segments:True` (mitigates allocator fragmentation). If startup instead fails with `Not enough memory … increase --mem-fraction-static`, the KV pool is too small — see [Troubleshooting](#troubleshooting).

### Serve long contexts

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [`--enable-prefill-cp`](#parallelism) + [`--attn-cp-size`](#parallelism) + [`--cp-strategy`](#parallelism) | Shards one sequence's KV and attention across devices | More communication; strategy is model-specific; `--attn-cp-size` must divide TP |
| [`--max-prefill-tokens`](#prefill-tuning) | Admits a full long sequence per prefill batch | Large values need an explicit `--mem-fraction-static` |
| [`--chunked-prefill-size -1`](#prefill-tuning) on a dedicated prefill pool | Entire sequence prefilled in one pass | No decode interleaving on that node |

### Scale beyond one node

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [PD disaggregation](#pd-disaggregation) | Prefill and decode tuned separately on their own nodes | More nodes and a router to operate |
| [`HCCL_SOCKET_IFNAME`](#communication-configuration) / `GLOO_SOCKET_IFNAME` | Required for multi-node HCCL/Gloo rendezvous | Must be an interface reachable from every node |

Also consider: `DEEPEP_HCCL_BUFFSIZE` per role (prefill `1200`, decode `400`).

## Scenario Checklists

Ordered starting points for each deployment shape, distilled from the published best practices. Values are from the DeepSeek V3.2 PD configuration unless noted — adjust them to your hardware and workload.

### Single-Node Mixed Serving

Both prefill and decode run on the same node, so each setting below must hold for both phases. Apply them in this order:

<Steps>
  <Step title="Set the topology">
    `--tp-size` = the number of NPUs used. For MoE models, add `--moe-a2a-backend deepep` — the EP size then follows TP.

    **Why:** topology constrains everything else. See [Parallelism](#parallelism).
  </Step>

  <Step title="Size the memory fraction after everything else">
    With the topology, graph, and speculative settings already fixed, size `--mem-fraction-static`. Start from a same-class best practice, lower it if OOM errors occur, and raise it when KV cache capacity limits concurrency.

    **Why:** activation and graph buffers are inputs to the memory budget. See [Memory and Device Configuration](#memory-and-device-configuration).
  </Step>

  <Step title="Keep chunked prefill enabled">
    Leave chunked prefill on; the NPU defaults select 4K or 8K according to device memory.

    **Why:** chunking interleaves prefill with decode in mixed workloads.
  </Step>

  <Step title="Keep NPU Graph on and size the decode buckets">
    Leave NPU Graph enabled, and set `--cuda-graph-max-bs-decode` near your typical per-rank batch size, as a multiple of `attn_tp_size`.

    **Why:** graphs remove kernel-launch overhead, and buckets below `attn_tp_size` cause capture to fail.
  </Step>

  <Step title="Add speculative decoding (optional)">
    Use `NEXTN` for models with an MTP head, and `EAGLE3` otherwise.

    **Why:** it reduces per-token latency.
  </Step>

  <Step title="Leave the task queue at level 1">
    Keep `TASK_QUEUE_ENABLE` at `1` on a mixed node.

    **Why:** mixed nodes capture decode graphs, and level `2` is incompatible with graph capture.
  </Step>
</Steps>

### PD Disaggregation (by Role)

Prefill and decode run on separate node groups, each configured for its own workload, and a router exposes both as one service. Pick the role you are configuring:

<Tabs>
  <Tab title="Prefill">

The prefill group runs prefill only, so it can take large un-chunked batches and leave graph capture off. Apply these steps in order:

<Steps>
  <Step title="Join the group as prefill">
    Pass `--disaggregation-mode prefill` and `--disaggregation-transfer-backend ascend`, then export `ASCEND_MF_STORE_URL=tcp://<this node's IP>:<port>`.

    **Why:** the MemFabric rendezvous store runs on the prefill primary node.
  </Step>

  <Step title="Turn off chunked prefill">
    Pass `--chunked-prefill-size -1`.

    **Why:** the group does not interleave with decode.
  </Step>

  <Step title="Bound one prefill batch">
    Set `--max-prefill-tokens` to approximately the target sequence length; the V3.2 reference uses `68000`.

    **Why:** it caps a single prefill batch.
  </Step>

  <Step title="Dedicate the group to one request at a time">
    Set `--max-running-requests 1`.

    **Why:** each request then has the entire node, which maximizes per-request prefill throughput.
  </Step>

  <Step title="Skip prefix caching when inputs share no prefixes">
    Add `--disable-radix-cache`.

    **Why:** it saves memory; keep caching on for shared-prefix traffic.
  </Step>

  <Step title="Pass no prefill graph flag">
    NPU prefill graphs are off by default, so no flag is needed. Do not use `--disable-cuda-graph`: on a mixed node it also disables decode capture.

    **Why:** graphs add little for large, variable prefill batches.
  </Step>

  <Step title="Add context parallelism for long contexts">
    Pass `--enable-prefill-cp`, `--attn-cp-size <tp>`, and `--cp-strategy interleave`. The strategy flag is required — V3.2/DSA uses `interleave`, MiMo V2 uses `zigzag` — and `--attn-cp-size` must divide TP.

    **Why:** it distributes the KV cache across devices.
  </Step>

  <Step title="Use DeepEP normal mode">
    Set `--moe-a2a-backend deepep` and `--deepep-mode normal`, plus `DEEPEP_HCCL_BUFFSIZE=1200`.

    **Why:** normal mode is the bulk dispatch path for large token counts.
  </Step>

  <Step title="Raise the task queue to level 2">
    Set `TASK_QUEUE_ENABLE=2`.

    **Why:** it pipelines task submission aggressively, and it is safe here because prefill captures no graphs.
  </Step>

  <Step title="Quantize dispatch">
    On multi-node prefill, prefer `--deepep-dispatcher-output-dtype int8` on newer versions; `DEEP_NORMAL_MODE_USE_INT8_QUANT=1` is deprecated — see the [reference](#moe-dispatch-and-expert-load-balancing).

    **Why:** it reduces dispatch communication volume.
  </Step>

  <Step title="Open the bootstrap port">
    Set `--disaggregation-bootstrap-port 8998`.

    **Why:** the router and decode nodes use this port to reach the prefill bootstrap service.
  </Step>
</Steps>

  </Tab>

  <Tab title="Decode">

Decode is latency-bound, so the steps below keep per-rank batches small and capture graphs. Apply them in this order:

<Steps>
  <Step title="Join the group as decode">
    Pass `--disaggregation-mode decode` and `--disaggregation-transfer-backend ascend`, then point `ASCEND_MF_STORE_URL` at the prefill primary node: `tcp://<prefill primary IP>:<port>`.

    **Why:** decode nodes discover the KV transfer service through the store, and the default transfer backend does not work on NPU.
  </Step>

  <Step title="Enable attention DP and the DP LM head">
    Pass `--attn-dp-size 8` and `--enable-dp-lm-head`. Attention DP must divide TP; with `deepep`, EP is forced to TP (`32`), so the published config still passes `--ep 32`.

    **Why:** attention DP removes KV duplication across the TP group.
  </Step>

  <Step title="Switch DeepEP to low-latency mode">
    Set `--moe-a2a-backend deepep` and `--deepep-mode low_latency`, plus `DEEPEP_HCCL_BUFFSIZE=400`.

    **Why:** low-latency mode is the small-batch dispatch path.
  </Step>

  <Step title="Cap concurrency and size the dispatch buffer">
    Set `--max-running-requests 32`, then `SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK=8`.

    **Why:** `8` = (32 requests / DP 8) × 4 draft tokens. Size it to the actual per-iteration maximum — see the [sizing note](#moe-dispatch-and-expert-load-balancing).
  </Step>

  <Step title="Lower the task queue to level 0">
    Set `TASK_QUEUE_ENABLE=0`.

    **Why:** decode captures NPU graphs, and level `2` is incompatible with graph capture.
  </Step>

  <Step title="Capture a small decode bucket">
    Set `--cuda-graph-max-bs-decode 4`.

    **Why:** it is near the typical batch size, balancing coverage against capture cost.
  </Step>

  <Step title="Enable speculative decoding">
    Pass `--speculative-algorithm NEXTN`, `--speculative-num-steps 3`, `--speculative-eagle-topk 1`, and `--speculative-num-draft-tokens 4`, then set `SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1`.

    **Why:** it reduces per-token latency.
  </Step>

  <Step title="Skip the scheduler all-gather (balanced load only)">
    With balanced DP load, set `SGLANG_SCHEDULER_SKIP_ALL_GATHER=1` and leave `--load-balance-method auto` — decode resolves to `round_robin`.

    **Why:** it removes scheduler sync latency, but it is safe only when every DP rank sees the same forward mode and token counts.
  </Step>
</Steps>

  </Tab>

  <Tab title="Router">

One router serves both groups and exposes a single OpenAI-compatible endpoint. Start it after both groups are up:

<Steps>
  <Step title="Reuse the prefill bootstrap port">
    Point the router at the same bootstrap port the prefill group sets (`8998`).

    **Why:** the router passes it to decode nodes when opening the prefill connection.
  </Step>

  <Step title="Launch the router">
    ```bash
    python -m sglang_router.launch_router --pd-disaggregation \
      --policy cache_aware \
      --prefill http://<prefill-ip>:8000 8998 \
      --decode http://<decode-ip>:8001 \
      --host 127.0.0.1 --port 6688 --mini-lb
    ```

    **Why:** it exposes one endpoint; without the router, the two groups are not reachable as a single service.
  </Step>
</Steps>

  </Tab>

</Tabs>

### Multi-Node

These settings only matter once prefill or decode spans more than one node. Apply them in this order:

<Steps>
  <Step title="Pin the HCCL and Gloo interfaces">
    **[Required]** Set `HCCL_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME` to an interface reachable from every node.

    **Why:** an unreachable interface makes HCCL/Gloo initialization hang or fail.
  </Step>

  <Step title="Size the DeepEP HCCL buffers per role">
    Set `DEEPEP_HCCL_BUFFSIZE` to `1200` on prefill and `400` on decode.

    **Why:** larger buffers carry bulk inter-node transfers but cost HBM, and decode needs less.
  </Step>

  <Step title="Quantize dispatch on prefill">
    Set `DEEP_NORMAL_MODE_USE_INT8_QUANT=1` — deprecated; prefer `--deepep-dispatcher-output-dtype int8`.

    **Why:** it lowers dispatch traffic.
  </Step>

  <Step title="Gather less after the Q projection (DeepSeek R1)">
    On DeepSeek R1 prefill, set `SGLANG_USE_AG_AFTER_QLORA=1` together with `--enable-attn-tp-input-scattered`.

    **Why:** it gathers fewer bytes after the low-rank Q projection; without the scattered-input flag the env var has no effect.
  </Step>

  <Step title="Copy the launch flags from the best-practice script">
    Set `--nnodes`, `--node-rank`, and `--dist-init-addr`, plus the remaining environment variables, from the best-practice script for your model.

    **Why:** the published scripts carry the complete validated set for each model.
  </Step>
</Steps>

## Troubleshooting

| Symptom | Likely Cause | Fix |
| ------- | ------------ | --- |
| Startup fails with `Not enough memory. Please try to increase --mem-fraction-static` | The KV pool sized to zero tokens once weights were loaded | Increase `--mem-fraction-static` in small steps; the message means the pool is too small, not that the model is too large |
| OOM during serving or graph capture | `--mem-fraction-static` leaves no headroom for activations or graph buffers, or the weights are BF16 | Lower `--mem-fraction-static`; if the model is BF16, load a ModelSlim W8A8/W4A4 checkpoint (`--quantization modelslim` loads pre-quantized checkpoints only) |
| NPU Graph capture aborts with `Do not support TASK_QUEUE_ENABLE = 2` | Level-2 task queue is incompatible with graph capture | Set `TASK_QUEUE_ENABLE=0` (or `1`) on the role that captures graphs |
| DeepEP dispatch fails at runtime | Per-rank dispatch tokens exceed the buffer | Size `SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK` to the actual per-iteration maximum (see the [reference](#moe-dispatch-and-expert-load-balancing)); raising it pads every low-latency iteration, and the `1024` cap does not apply to `ascend_fuseep` |
| Multi-node HCCL/Gloo initialization hangs or fails | Auto-selected interface not reachable across nodes | Set `HCCL_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME` to an interface reachable from every node |
| PD decode node fails to start or cannot reach the prefill bootstrap | Transfer backend left at the default, or a wrong store address | Pass `--disaggregation-transfer-backend ascend` and set `ASCEND_MF_STORE_URL=tcp://<prefill primary IP>:<port>` |
| Intermittent pinned host memory allocation failures | Pinned host pool fragmentation | Append `pin_memory_expandable_segments:True` to `PYTORCH_NPU_ALLOC_CONF`; requires CANN 8.5.0 / driver 25.5.0 or newer, otherwise it is silently reset to `False` |
| Expert hotspots / uneven expert load across NPUs | Static expert placement | `--enable-eplb` (requires the `deepep` backend, `TP = EP = world size`, and `--ep-num-redundant-experts`) |
| Startup fails with `--cp-strategy must be set when --enable-prefill-cp is enabled` | Prefill CP enabled without a strategy | Add `--cp-strategy interleave` for DeepSeek V3.2/DSA, or `zigzag` for MiMo V2 |
| NPU Graph capture fails with an empty capture list | `--cuda-graph-max-bs-decode` is below `attn_tp_size` or not a multiple of it | Raise it to at least `attn_tp_size` and use a multiple |
| PD decode cannot reach the prefill bootstrap | Missing or wrong `--disaggregation-bootstrap-port`, or the router was not launched | Set the port on the prefill group and pass the same port in the router's `--prefill` address |

## Parameter Reference

Each table below gives the **tuned reference value**, not the flag default. Role-specific values are written as `Prefill:`/`Decode:`; the `Default` column in the [Feature Support Matrix](/docs/hardware-platforms/ascend-npus/reference/support_features) has the raw default for every flag, and [Feature descriptions](#feature-descriptions) maps each Ascend feature to its switch.

### Feature descriptions

Each Ascend-relevant feature with its switch and default. The **Reference Value** columns below give tuned starting points; this table indicates which parameter a feature name refers to.

| Feature | Switch | Default | Notes |
| --- | --- | --- | --- |
| Tensor Parallelism | `--tp-size` | `1` | Shards weights across devices; every extra rank adds all-reduce. |
| Attention Data Parallelism | `--attn-dp-size` (alias `--attention-data-parallel-size`) | `1` | Runs attention data-parallel inside the TP group; must divide TP; cannot combine with `--dp-size` greater than 1. The best-practice spelling `--enable-dp-attention --dp-size N` is deprecated. |
| Expert Parallelism | `--ep-size` (aliases `--ep`, `--expert-parallel-size`) | `1` | With `deepep`, EP is forced to TP; `ascend_fuseep` can use a different value. |
| Context Parallelism (prefill) | `--enable-prefill-cp` + `--attn-cp-size` + `--cp-strategy` | off; `1`; unset | All three are required for prefill CP; `--attn-cp-size` must divide TP. V3.2/DSA uses `interleave`, MiMo V2 uses `zigzag`. |
| PD Disaggregation | `--disaggregation-mode` + `--disaggregation-transfer-backend ascend` + `ASCEND_MF_STORE_URL` | off; `mooncake`; unset | The store runs on the prefill primary node; launch a router with `--pd-disaggregation` to expose one endpoint. |
| Quantization | `--quantization modelslim` | auto-detected | ModelSlim W4A4/W8A8/W4A8 and MXFP8/MXFP4 checkpoints. Never disable the NZ weight layout for FP4/MXFP4. |
| Chunked Prefill | `--chunked-prefill-size` | 4K/8K by HBM tier | `-1` disables chunking; with attention DP the per-rank chunk is divided by `--attn-dp-size`. |
| NPU Graph | `--cuda-graph-backend-decode`, `--cuda-graph-bs-decode`, `--cuda-graph-max-bs-decode` | decode `full`; prefill `disabled` | Decode-only on NPU. `--cuda-graph-max-bs-decode` is per DP rank and must be at least, and a multiple of, `attn_tp_size`. |
| Speculative Decoding | `--speculative-algorithm` + steps/topk/draft-token flags | off | NEXTN, EAGLE, and EAGLE3 are the validated Ascend paths. Keep `--speculative-eagle-topk 1`; with topk 1, draft tokens are forced to `num-steps + 1`. |
| Prefix cache (radix) | `--disable-radix-cache` | enabled | PD decode forces it off unless `--disaggregation-decode-enable-radix-cache` is set. |
| Overlap schedule | `--disable-overlap-schedule` | enabled | Prepared on CPU while the current batch runs; auto-disabled for pipeline parallelism. |
| DP LM Head | `--enable-dp-lm-head` | off | Requires attention DP (`--attn-dp-size` greater than 1). |
| MLAPO | `SGLANG_NPU_USE_MLAPO=1` | off | Fuses MLA pre-processing (projections, RMSNorms, RoPE, KV write). Can silently fall back to the unfused path on unsupported weight layouts. |
| Multistream MoE | `SGLANG_NPU_USE_MULTI_STREAM=1` | off | Runs shared and routed experts on separate streams. |
| EPLB | `--enable-eplb` | off | Requires the `deepep` backend, `TP = EP = world size`, and `--ep-num-redundant-experts` for replication. |
| NZ weight layout | `SGLANG_NPU_DISABLE_ACL_FORMAT_WEIGHT=1` to disable | enabled | Keep the default; never disable it for FP4/MXFP4. KV-cache NZ is controlled separately by `SGLANG_USE_FIA_NZ`. |

### System-Level Optimizations

These OS-level settings reduce scheduling jitter on the host CPUs. Run the host-level commands as root (or with `sudo`); export environment variables in the launch shell.

<table>
  <thead>
    <tr>
      <th>Command / Variable</th>
      <th>Purpose</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`echo performance | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor`</td>
      <td>Locks all CPU cores at the maximum frequency to remove DVFS-induced latency jitter.</td>
    </tr>
    <tr>
      <td>`sudo sysctl -w vm.swappiness=0`</td>
      <td>Reduces the chance of kernel swapping, lowering page faults on host memory used by NPU buffers.</td>
    </tr>
    <tr>
      <td>`sudo sysctl -w kernel.numa_balancing=0`</td>
      <td>Stops the kernel from migrating pages between NUMA nodes while inference is running.</td>
    </tr>
    <tr>
      <td>`sudo sysctl -w kernel.sched_migration_cost_ns=50000`</td>
      <td>Discourages the scheduler from moving inference threads between CPU cores.</td>
    </tr>
    <tr>
      <td>`export SGLANG_SET_CPU_AFFINITY=1`</td>
      <td>Binds each TP rank's scheduler process to dedicated CPU cores, avoiding cross-core migration overhead.</td>
    </tr>
  </tbody>
</table>

### Memory and Device Configuration

<table>
  <thead>
    <tr>
      <th>Variable / Argument</th>
      <th>Purpose</th>
      <th>Reference Value</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`PYTORCH_NPU_ALLOC_CONF=expandable_segments:True`</td>
      <td>Reserves the address space up front and maps physical pages on demand, resisting allocator fragmentation — the main defense against out-of-memory errors on MoE-scale models.</td>
      <td>`expandable_segments:True`</td>
    </tr>
    <tr>
      <td>`PYTORCH_NPU_ALLOC_CONF=expandable_segments:True,pin_memory_expandable_segments:True`</td>
      <td>Also grows pinned host memory on demand. Helps when large pinned allocations (HiCache host pool, KV cache offload) fail intermittently; changes memory usage, so validate on your workload.</td>
      <td>`expandable_segments:True,pin_memory_expandable_segments:True` (not used in published best practices — validate on your cluster)</td>
    </tr>
    <tr>
      <td>`STREAMS_PER_DEVICE=32`</td>
      <td>Size of the per-device stream pool. Only `8` and `32` are valid (other values are reset to `32`), so keep the default unless profiling indicates a need for `8`.</td>
      <td>`32`</td>
    </tr>
    <tr>
      <td>`--mem-fraction-static`</td>

### Parallelism

SGLang shards a model along several axes that combine as `tp_size = attn_tp_size × attn_dp_size × attn_cp_size`:

<table>
  <thead>
    <tr>
      <th>Argument / Variable</th>
      <th>Purpose</th>
      <th>Reference Value</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`--tp-size`</td>
      <td>Shards every weight tensor across devices, which communicate via HCCL all-reduce. The primary way to fit models larger than a single device. Use the smallest TP that fits the model per node — every extra TP rank adds all-reduce communication.</td>
      <td>`32`</td>
    </tr>
    <tr>
      <td>`--dp-size`</td>

      <td>`1`</td>
    </tr>
    <tr>
      <td>`--attn-dp-size` / `--attention-data-parallel-size`</td>

Must divide the TP size; a key decode-throughput lever for MoE models. The best-practice scripts still use `--enable-dp-attention --dp-size 8` (deprecated) — prefer `--attn-dp-size 8`.</td>

    <tr>

      <td>Enabled</td>

### Speculative Decoding

Speculative decoding drafts several tokens per step and verifies them in one target forward pass, reducing per-token latency. For non-greedy requests, the Ascend target verification applies request-level `temperature`, `top_k`, and `top_p`; classic rejection sampling is also available via `--speculative-use-rejection-sampling` (linear candidates only, requires `--speculative-eagle-topk 1`, and is incompatible with non-default accept thresholds and deterministic inference):

<table>
  <thead>
    <tr>
      <th>Argument / Variable</th>
      <th>Purpose</th>

    </tr>
  </thead>

    <tr>
      <td>`--speculative-algorithm`</td>
      <td>`NEXTN` (alias of `EAGLE`) uses the model's own MTP head, requiring no separate draft model (DeepSeek V3.2/R1). `EAGLE3` uses an external draft model (Qwen MoE). Ascend-validated paths are `NEXTN`, `EAGLE`, and `EAGLE3`; `DFLASH`/`DSPARK` have NPU backends but are not covered by the published best practices, and `STANDALONE`/`UNO` are unverified on NPU. **Symbols:** 🟢 supported and exercised together; 🟠 supported only with the constraint in the row; ❌ do not combine.

| Feature A | Feature B | Status | Constraint |
| --- | --- | --- | --- |
| NPU Graph | TP, attention DP, EP, PD, quantization, speculative decoding, DP LM Head | 🟢 | Used together in the published DeepSeek V3.2 decode configuration. |
| Chunked Prefill | TP, attention DP, EP, context parallelism, quantization | 🟢 | Default-on for mixed serving; per-rank chunk is divided by attention DP. |
| PD Disaggregation | DP LM Head | 🟢 | Used together on DeepSeek V3.2 decode. |
| Quantization | DP LM Head | 🟢 | Used together on DeepSeek V3.2 decode (`modelslim`). |

| PD decode | Prefix cache | 🟠 | Decode forces radix caching off; enable it only with the experimental `--disaggregation-decode-enable-radix-cache`. |
| Speculative decoding | Quantized target | 🟠 | The draft inherits the target quantization by default; pass `--speculative-draft-model-quantization unquant`. |
| EPLB | `ascend_fuseep` | ❌ | EPLB requires `deepep`; there is no startup guard today, so a wrong backend can fail silently. |
| EPLB | Topology | ❌ unless `TP = EP = world size` | Migration asserts `tp_size == moe_ep_size == world_size`. |
