This guide helps you tune SGLang deployments on Ascend NPU. Use it in one of two ways:

- **Tune for a goal**: start with [How to Tune](#how-to-tune), pick your goal in [Tuning by Goal](#tuning-by-goal), then follow a [scenario checklist](#scenario-checklists).
- **Look up a parameter**: jump directly to the relevant section of the [Parameter Reference](#parameter-reference) from the table of contents.

Reference values are drawn from the published best-practice configurations — primarily the
[DeepSeek-V3.2 PD disaggregation configuration](/docs/hardware-platforms/ascend-npus/model-deployment/best-practices/deepseek_v3_2#pd-disaggregation) —
with the source model noted where it differs. For complete deployment scripts and benchmark results, see the
[Ascend NPU Best Practice](/docs/hardware-platforms/ascend-npus/model-deployment/best-practices/deepseek_r1) page.

<Note>
  Parameters fall into two categories:

  - **Required configurations** (marked with `[Required]`): must be set correctly for the target deployment scenario (e.g., multi-node communication, PD disaggregation). Incorrect values cause deployment failures or incorrect behavior.
  - **Performance optimizations**: improve throughput, latency, or memory efficiency. The optimal value depends on your model, hardware, and workload — treat the reference values as starting points, not defaults.
</Note>

## How to Tune

1. **Define the goal and measure a baseline.** Pick the metric that matters — TTFT (time to first token), TPOT (time per output token), throughput (tokens/s), or memory headroom — and benchmark the current configuration before changing anything. The [best practices](/docs/hardware-platforms/ascend-npus/model-deployment/best-practices/deepseek_r1) ship ready-to-use `sglang.bench_serving` commands for each model.
2. **Tune top-down.** Settle the deployment topology first (parallelism, PD disaggregation), then memory (`--mem-fraction-static`, quantization), then communication (interfaces, buffers), and only then kernel-level switches (NPU Graph, speculative decoding). Higher levels bound what lower levels can achieve — no amount of graph tuning compensates for a wrong TP/EP split.
3. **Change one knob at a time, re-measure, keep the winner.** Record every configuration you benchmark so results stay comparable.

## Tuning by Goal

Where to start for common tuning goals — follow the links for details:

| Goal                                        | Primary Knobs                                                                                                     | Also Consider                                              | Main Trade-off                                        |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------- |
| Lower decode latency (TPOT)                 | [Speculative decoding](#speculative-decoding), [`--cuda-graph-max-bs-decode`](#decode-tuning), [`--attn-dp-size`](#parallelism) | `SGLANG_SCHEDULER_SKIP_ALL_GATHER=1`                       | Spec decoding adds draft compute and depends on acceptance rate |
| Higher throughput                           | [`--attn-dp-size`](#parallelism), [`--max-running-requests`](#prefill-tuning), [`--tokenizer-worker-num`](#throughput-tuning) | [`--ep-size`](#parallelism)                                | Higher concurrency raises per-request latency         |
| Lower time to first token (TTFT)            | [`--chunked-prefill-size`](#prefill-tuning), prefix caching (leave [`--disable-radix-cache`](#prefill-tuning) unset) | [`--attn-cp-size`](#parallelism) for long inputs           | Chunking adds a small prefill overhead; CP adds communication |
| Resolve OOM                                 | Lower [`--mem-fraction-static`](#memory-and-device-configuration), [quantization](#quantization)                     | `PYTORCH_NPU_ALLOC_CONF=expandable_segments:True`          | Less KV cache capacity, or a small accuracy loss      |
| Serve long contexts                         | [`--attn-cp-size`](#parallelism), [`--max-prefill-tokens`](#prefill-tuning)                                       | `--chunked-prefill-size -1` on a dedicated prefill pool    | More inter-device communication                       |
| Scale beyond one node                       | [PD disaggregation](#pd-disaggregation), [`HCCL_SOCKET_IFNAME`](#communication-configuration)                     | `DEEPEP_HCCL_BUFFSIZE`                                     | More operational complexity                           |

## Scenario Checklists

Ordered starting points for each deployment shape, distilled from the published best practices. Values are from the DeepSeek V3.2 PD configuration unless noted — adjust them to your hardware and workload.

### Single-Node Mixed Serving

| Step | Setting | Why |
| ---- | ------- | --- |
| 1 | `--tp-size` = NPUs used; for MoE add `--moe-a2a-backend deepep` (EP size follows TP) | Topology bounds everything else — see [Parallelism](#parallelism) |
| 2 | After settling topology, graph, and speculation, size `--mem-fraction-static`: start from a same-class best practice, lower it on OOM, raise it when KV cache limits concurrency | Activation and graph buffers are inputs to the memory budget; see [Memory & Device Configuration](#memory-and-device-configuration) |
| 3 | Keep chunked prefill enabled (NPU defaults pick 4K/8K by device memory) | Interleaves prefill with decode in mixed workloads |
| 4 | Leave NPU Graph on; set `--cuda-graph-max-bs-decode` near your typical per-rank batch size, as a multiple of `attn_tp_size` | Removes kernel-launch overhead; buckets below `attn_tp_size` fail capture |
| 5 | Optional: speculative decoding — `NEXTN` for models with MTP, `EAGLE3` otherwise | Cuts per-token latency |
| 6 | Leave `TASK_QUEUE_ENABLE` at `1` on a mixed node | Mixed nodes capture decode graphs; level `2` breaks capture |

### PD Disaggregation — Prefill

| Step | Setting | Why |
| ---- | ------- | --- |
| 1 | `--disaggregation-mode prefill --disaggregation-transfer-backend ascend`, `ASCEND_MF_STORE_URL=tcp://<this node's IP>:<port>` | The MemFabric rendezvous store runs on the prefill primary node |
| 2 | `--chunked-prefill-size -1` | Dedicated prefill: no interleaving with decode |
| 3 | `--max-prefill-tokens` ≈ target sequence length (V3.2: `68000`) | Bounds one prefill batch |
| 4 | `--max-running-requests 1` | Dedicates the whole node to each request |
| 5 | `--disable-radix-cache` when inputs share no prefixes | Saves memory; keep caching on for shared-prefix traffic |
| 6 | No prefill graph flag is needed: NPU prefill graphs are off by default. Do not use `--disable-cuda-graph` on a mixed node | Graphs add little for large, variable prefill batches; the deprecated flag also disables decode capture |
| 7 | For long contexts: `--enable-prefill-cp --attn-cp-size <tp> --cp-strategy interleave` | Distributes KV cache across devices. `--cp-strategy` is required; V3.2/DSA uses `interleave`, MiMo V2 uses `zigzag`; `--attn-cp-size` must divide TP |
| 8 | `--moe-a2a-backend deepep --deepep-mode normal`, `DEEPEP_HCCL_BUFFSIZE=1200` | Bulk token dispatch |
| 9 | `TASK_QUEUE_ENABLE=2` | Aggressive submission pipelining — safe here because prefill captures no graphs |
| 10 | Multi-node prefill: `DEEP_NORMAL_MODE_USE_INT8_QUANT=1` (deprecated — see the [reference](#moe-dispatch-and-expert-load-balancing)); prefer `--deepep-dispatcher-output-dtype int8` on newer versions | Cuts dispatch communication volume |
| 11 | `--disaggregation-bootstrap-port 8998` | The router and decode nodes use this port to reach the prefill bootstrap service |

### PD Disaggregation — Decode

| Step | Setting | Why |
| ---- | ------- | --- |
| 1 | `--disaggregation-mode decode --disaggregation-transfer-backend ascend`, `ASCEND_MF_STORE_URL=tcp://<prefill primary IP>:<port>` | Decode nodes discover the KV transfer service through the store; the default transfer backend does not work on NPU |
| 2 | `--attn-dp-size 8` + `--enable-dp-lm-head` | Attention DP removes KV duplication; must divide TP. With `deepep`, EP is forced to TP (`32`), so the BP still passes `--ep 32` |
| 3 | `--moe-a2a-backend deepep --deepep-mode low_latency`, `DEEPEP_HCCL_BUFFSIZE=400` | Small-batch dispatch path |
| 4 | `--max-running-requests 32`, then `SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK=8` | `8` = (32 requests / DP 8) × 4 draft tokens. Size it to the real per-iteration maximum; see the sizing note in the [reference](#moe-dispatch-and-expert-load-balancing) |
| 5 | `TASK_QUEUE_ENABLE=0` | Decode captures NPU graphs — level 2 breaks capture |
| 6 | `--cuda-graph-max-bs-decode 4` | Near the typical batch size; balances coverage vs capture cost |
| 7 | `--speculative-algorithm NEXTN --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`, `SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1` | Cuts per-token latency |
| 8 | `SGLANG_SCHEDULER_SKIP_ALL_GATHER=1` with balanced DP load (leave `--load-balance-method auto`; decode resolves to `round_robin`) | Removes scheduler sync latency; only safe when DP ranks see the same forward mode and token counts |

### PD Disaggregation — Router

| Step | Setting | Why |
| ---- | ------- | --- |
| 1 | Use the same bootstrap port (`8998`) that the prefill group sets | The router passes it to decode nodes when opening the prefill connection |
| 2 | `python -m sglang_router.launch_router --pd-disaggregation --policy cache_aware --prefill http://<prefill-ip>:8000 8998 --decode http://<decode-ip>:8001 --host 127.0.0.1 --port 6688 --mini-lb` | Exposes one OpenAI-compatible endpoint; without it the two server groups are not reachable as one service |

### Multi-Node

| Step | Setting | Why |
| ---- | ------- | --- |
| 1 | [Required] `HCCL_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME` = an interface reachable from every node | An unreachable interface makes HCCL/Gloo initialization hang or fail |
| 2 | `DEEPEP_HCCL_BUFFSIZE` per role (prefill `1200`, decode `400`) | Larger buffers for bulk inter-node transfers |
| 3 | `DEEP_NORMAL_MODE_USE_INT8_QUANT=1` on prefill (deprecated) | Less dispatch traffic |
| 4 | DeepSeek R1 prefill: `SGLANG_USE_AG_AFTER_QLORA=1` together with `--enable-attn-tp-input-scattered` | Gathers fewer bytes after the low-rank Q projection; without the scattered-input flag the env var is a no-op |
| 5 | Launch flags (`--nnodes`, `--node-rank`, `--dist-init-addr`) and remaining env vars | Copy the complete set from the best-practice scripts for your model |

## Troubleshooting Quick Fixes

| Symptom | Likely Cause | Fix |
| ------- | ------------ | --- |
| Startup fails with `Not enough memory. Please try to increase --mem-fraction-static` | KV cache pool too small once weights are loaded | Increase `--mem-fraction-static` |
| OOM during serving or graph capture | `--mem-fraction-static` too high, or weights unquantized | Lower `--mem-fraction-static`; or use `--quantization modelslim` |
| NPU Graph capture aborts with `Do not support TASK_QUEUE_ENABLE = 2` | Level-2 task queue is incompatible with graph capture | Set `TASK_QUEUE_ENABLE=0` (or `1`) on the role that captures graphs |
| DeepEP dispatch fails at runtime | Per-rank dispatch tokens exceed the buffer | Raise `SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK` (hard cap `1024`) to cover the per-rank tokens of one iteration |
| Multi-node HCCL/Gloo initialization hangs or fails | Auto-selected interface not reachable across nodes | Set `HCCL_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME` to an interface reachable from every node |
| PD decode node fails to start or cannot reach the prefill bootstrap | Transfer backend left at the default, or a wrong store address | Pass `--disaggregation-transfer-backend ascend` and set `ASCEND_MF_STORE_URL=tcp://<prefill primary IP>:<port>` |
| Intermittent pinned host memory allocation failures | Pinned host pool fragmentation | Append `pin_memory_expandable_segments:True` to `PYTORCH_NPU_ALLOC_CONF` |
| Expert hotspots / uneven expert load across NPUs | Static expert placement | `--enable-eplb` (requires the `deepep` backend) |

### Feature descriptions

Each Ascend-relevant feature, its switch, and its default. The **Reference Value** columns below give tuned starting points; this table tells you which knob a feature name refers to.

| Feature | Switch | Default | Notes |
| --- | --- | --- | --- |
| Tensor Parallelism | `--tp-size` | `1` | Shards weights across devices; every extra rank adds all-reduce. |
| Attention Data Parallelism | `--attn-dp-size` (alias `--attention-data-parallel-size`) | `1` | Runs attention data-parallel inside the TP group; must divide TP; cannot combine with `--dp-size` greater than 1. The best-practice spelling `--enable-dp-attention --dp-size N` is deprecated. |
| Expert Parallelism | `--ep-size` (aliases `--ep`, `--expert-parallel-size`) | `1` | With `deepep`, EP is forced to TP; `ascend_fuseep` can use a different value. |
| Context Parallelism (prefill) | `--enable-prefill-cp` + `--attn-cp-size` + `--cp-strategy` | off; `1`; unset | All three are required for prefill CP; `--attn-cp-size` must divide TP. V3.2/DSA uses `interleave`, MiMo V2 uses `zigzag`. |
| PD Disaggregation | `--disaggregation-mode` + `--disaggregation-transfer-backend ascend` + `ASCEND_MF_STORE_URL` | off; `mooncake`; unset | The store runs on the prefill primary node; launch a router with `--pd-disaggregation` to expose one endpoint. |
| Quantization | `--quantization modelslim` | auto-detected | ModelSlim W4A4/W8A8/W4A8 and MXFP8/MXFP4 checkpoints. Never disable the NZ weight layout for FP4/MXFP4. |
| Chunked Prefill | `--chunked-prefill-size` | 4K/8K by HBM tier | `-1` disables chunking; with attention DP the per-rank chunk is divided by `--attn-dp-size`. |
| NPU Graph | `--cuda-graph-backend-decode`, `--cuda-graph-bs-decode`, `--cuda-graph-max-bs-decode` | decode `full`; prefill `disabled` | Decode-only on NPU. `--cuda-graph-max-bs-decode` is per DP rank and must be at least, and a multiple of, `attn_tp_size`. |
| Speculative Decoding | `--speculative-algorithm` + steps/topk/draft-token flags | off | NEXTN, EAGLE, and EAGLE3 are the validated Ascend paths. Keep `--speculative-eagle-topk 1`; with topk 1, draft tokens are forced to `num-steps + 1`. |
| Prefix cache (radix) | `--disable-radix-cache` | enabled | PD decode forces it off unless `--disaggregation-decode-enable-radix-cache` is set. |
| Overlap schedule | `--disable-overlap-schedule` | enabled | Prepared on CPU while the current batch runs; auto-disabled for pipeline parallelism. |
| DP LM Head | `--enable-dp-lm-head` | off | Requires attention DP (`--attn-dp-size` greater than 1). |
| MLAPO | `SGLANG_NPU_USE_MLAPO=1` | off | Fuses MLA pre-processing (projections, RMSNorms, RoPE, KV write). Can silently fall back to the unfused path on unsupported weight layouts. |
| Multistream MoE | `SGLANG_NPU_USE_MULTI_STREAM=1` | off | Runs shared and routed experts on separate streams. |
| EPLB | `--enable-eplb` | off | Requires the `deepep` backend, `TP = EP = world size`, and `--ep-num-redundant-experts` for replication. |
| NZ weight layout | `SGLANG_NPU_DISABLE_ACL_FORMAT_WEIGHT=1` to disable | enabled | Keep the default; never disable it for FP4/MXFP4. KV-cache NZ is controlled separately by `SGLANG_USE_FIA_NZ`. |

### Memory and Device Configuration

<table>
  <thead>
    <tr>
      <th>Variable / Argument</th>
      <th>Purpose</th>

  </thead>

    <tr>
      <td>`PYTORCH_NPU_ALLOC_CONF=expandable_segments:True`</td>

    </tr>
    <tr>
      <td>`STREAMS_PER_DEVICE=32`</td>
      <td>Size of the per-device stream pool. Only `8` and `32` are valid (other values are reset to `32`), so keep the default unless profiling gives a reason to use `8`.</td>
      <td>`32`</td>
    </tr>
    <tr>
      <td>`--mem-fraction-static`</td>
      <td>Fraction of NPU memory reserved for model weights and the KV cache pool. Higher means more KV cache for concurrent requests; lower leaves headroom for activations. Raise gradually while watching for out-of-memory errors.</td>
      <td>Prefill: `0.73`, Decode: `0.79`</td>
    </tr>
  </tbody>
</table>

### Parallelism

SGLang shards a model along several axes that combine as `tp_size = attn_tp_size × attn_dp_size × attn_cp_size`:

<table>
  <thead>
    <tr>
      <th>Argument / Variable</th>
      <th>Purpose</th>
      <th>Reference Value</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`--tp-size`</td>
      <td>Shards every weight tensor across devices, which communicate via HCCL all-reduce. The primary way to fit models larger than a single device. Use the smallest TP that fits the model per node — every extra TP rank adds all-reduce communication.</td>
      <td>`32`</td>
    </tr>
    <tr>
      <td>`--dp-size`</td>
      <td>Replicates the model across device groups to serve more requests in parallel. Cannot be combined with attention DP (`--attn-dp-size` greater than `1`); model replication is single-node only, enforced at startup.</td>
      <td>`1`</td>
    </tr>
    <tr>
      <td>`--attn-dp-size` / `--attention-data-parallel-size`</td>
      <td>Runs attention data-parallel inside the TP group: each DP group serves its own requests with its own KV cache and its own copy of the attention weights (still TP-sharded over the remaining `tp/attn_dp` ranks), while FFN/MoE layers stay TP/EP-sharded. Must divide the TP size; a key decode-throughput lever for MoE models. The BP spelling `--enable-dp-attention --dp-size 8` is deprecated — prefer `--attn-dp-size 8`.</td>
      <td>Decode: `8`</td>
    </tr>
    <tr>
      <td>`--attn-cp-size`</td>
      <td>Splits a single long sequence across devices for the prefill phase; it only shards context when `--enable-prefill-cp` is also set. Must divide `--tp-size` evenly (and `tp_size % (attn_dp_size × attn_cp_size) == 0` when both are used). Published configs range from `cp = tp` (V3.2, GLM-5.1) to `cp = 2, tp = 16` (Qwen3-235B).</td>
      <td>Prefill: `32`</td>
    </tr>
    <tr>
      <td>`--enable-prefill-cp`</td>
      <td>Enables context parallelism for the prefill phase. Required together with `--attn-cp-size` and `--cp-strategy`; without it, `--attn-cp-size` alone does not shard the prefill context. Prefill only — decode CP is a separate `--dcp-size` feature.</td>
      <td>Set on long-context prefill</td>
    </tr>
    <tr>
      <td>`--cp-strategy`</td>
      <td>Sharding strategy for prefill CP: `zigzag` (each rank gets early and late blocks) or `interleave` (token indices modulo CP size). Required when `--enable-prefill-cp` is set. Model rules: DeepSeek V3.2/DSA → `interleave`; MiMo V2 → `zigzag`; CP-TP sharing models (GLM-5.3/Qwen4Exp) → `zigzag` and `cp = tp`.</td>
      <td>V3.2: `interleave`</td>
    </tr>
    <tr>
      <td>`--ep-size` / `--ep` / `--expert-parallel-size`</td>
      <td>Distributes MoE experts across cards and routes tokens via all-to-all dispatch. Default `1`. With `deepep`, the final EP size is forced to TP (`ep_size` is adjusted automatically); only non-spanning backends such as `ascend_fuseep` can use a different value. DeepSeek V3.2 with 256 routed experts uses `32` because TP is `32`.</td>
      <td>`32`</td>
    </tr>
    <tr>
      <td>`--moe-dense-tp-size`</td>
      <td>TP size for the dense FFN layers of MoE models (`first_k_dense_replace`). Allowed values: unset (default), `1`, or the full TP size. Leave it unset for normal TP-sharded dense FFN; set `1` with attention DP to replicate the dense FFN per DP group and drop its all-reduce. Do not pass the TP size just to “match TP” — that turns on an extra attention-input gather.</td>
      <td>`1`</td>
    </tr>
    <tr>
      <td>`--enable-dp-lm-head`</td>
      <td>Shards the LM head vocabulary across the attention-TP group inside each DP rank, avoiding an all-gather of logits across DP ranks. Requires attention DP (`--attn-dp-size` > 1).</td>
      <td>Enabled</td>
    </tr>
    <tr>
      <td>`--load-balance-method`</td>
      <td>Routes requests across DP ranks: `auto` (default), `round_robin`, `total_tokens`, `total_requests`, or `follow_bootstrap_room`. `auto` resolves per role: `follow_bootstrap_room` on PD prefill, `round_robin` on decode and non-PD. Leave it at `auto` unless you have a reason; an explicit `round_robin` on PD prefill loses bootstrap-room affinity. Has no effect when `dp_size × attn_dp_size == 1`.</td>
      <td>`auto`</td>
    </tr>
    <tr>
      <td>`SGLANG_SCHEDULER_SKIP_ALL_GATHER=1`</td>
      <td>Skips the scheduler's cross-DP-rank metadata all-gather on every step (prefill, mixed, and decode), not only decode. Safe only when every DP rank computes the same forward mode and rank-invariant token counts (balanced/round-robin load); uneven load can desync MoE dispatch and graph buckets. There is no code guard that rejects it.</td>
      <td>`1`</td>
    </tr>
  </tbody>
</table>

### MoE Dispatch and Expert Load Balancing

MoE layers move tokens between ranks to reach their experts. On Ascend, the all-to-all backend is either DeepEP or Ascend FuseEP (a fused dispatch+GEMM+combine path):

<table>
  <thead>
    <tr>
      <th>Argument / Variable</th>
      <th>Purpose</th>
      <th>Reference Value</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`--moe-a2a-backend`</td>
      <td>All-to-all backend for MoE dispatch/combine: `deepep` (separate prefill/decode dispatch paths) or `ascend_fuseep` (a single fused dispatch+GEMM+combine kernel).</td>
      <td>`deepep`</td>
    </tr>
    <tr>
      <td>`--deepep-mode`</td>
      <td>DeepEP operating mode: `normal` (high throughput, large token counts — prefill), `low_latency` (small batches, graph-compatible — decode), or `auto` (per batch). Use `auto` unless prefill and decode are tuned separately in PD disaggregation.</td>
      <td>Prefill: `normal`, Decode: `low_latency`</td>
    </tr>
    <tr>
      <td>`SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK`</td>
      <td>Per-rank dispatch buffer capacity (in tokens) for DeepEP low-latency decode. Default `128`, hard cap `1024`. DeepEP normal mode ignores it, but the `ascend_fuseep` path uses it for prefill as well.</td>

    </tr>
    <tr>
      <td>`DEEP_NORMAL_MODE_USE_INT8_QUANT=1`</td>
      <td>Quantizes DeepEP dispatch activations to INT8, cutting communication volume at a small accuracy cost. Best for large-scale multi-node prefill. Deprecated: will become a no-op once the quantization behavior is inferred automatically (see the [environment variables reference](/docs/hardware-platforms/ascend-npus/reference/environment_variables)).</td>
      <td>Prefill: `1`</td>
    </tr>
    <tr>
      <td>`TASK_QUEUE_ENABLE`</td>

      <td>Prefill: `2`, Decode: `0`</td>
    </tr>
    <tr>
      <td>`--enable-eplb`</td>
      <td>Dynamically redistributes experts across devices based on measured load (deepseek-family balancing algorithms). Enable it when expert-distribution metrics show unbalanced load. Requires the `deepep` backend — `ascend_fuseep` is not supported (see the [feature support matrix](/docs/hardware-platforms/ascend-npus/reference/support_features)).</td>
      <td>As needed</td>

### Speculative Decoding

Speculative decoding drafts several tokens per step and verifies them in one target forward pass, cutting per-token latency. For non-greedy requests, the Ascend target verification applies request-level `temperature`, `top_k`, and `top_p`; classic rejection sampling is also available via `--speculative-use-rejection-sampling` (linear candidates only, requires `--speculative-eagle-topk 1`):

<table>
  <thead>
    <tr>
      <th>Argument / Variable</th>
      <th>Purpose</th>
      <th>Reference Value</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`--speculative-algorithm`</td>
      <td>`NEXTN` (alias of `EAGLE`) uses the model's own MTP head, requiring no separate draft model (DeepSeek V3.2/R1). `EAGLE3` uses an external draft model (Qwen MoE). Also `STANDALONE`, `DFLASH`, `DSPARK`, `UNO`, plus any plugin-registered name (`NGRAM` is CUDA/CPU/XPU-only).</td>
      <td>`NEXTN`</td>
    </tr>
    <tr>
      <td>`--speculative-num-steps`</td>
      <td>Draft forward passes per iteration. More steps raise acceptance length and throughput but add latency. Prefill `1`, decode `2`–`4`.</td>
      <td>Prefill: `1`, Decode: `3`</td>
    </tr>
    <tr>
      <td>`--speculative-eagle-topk`</td>
      <td>Draft candidates kept per position. On Ascend keep `1` — the page size is 128 and the ascend attention backend does not implement tree drafts (`topk` > 1); MTP and rejection sampling also require `1`.</td>
      <td>`1`</td>
    </tr>
    <tr>
      <td>`--speculative-num-draft-tokens`</td>
      <td>Draft tokens verified per iteration (with `topk 1`, `num-steps + 1`). More tokens raise potential acceptance length and throughput at a higher compute cost. Prefill `2`, decode `4`.</td>
      <td>Prefill: `2`, Decode: `4`</td>
    </tr>
    <tr>
      <td>`SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1`</td>
      <td>Runs speculative batch-preparation kernels (draft-extend metadata, KV-location planning) on a dedicated stream, overlapped with other work instead of serializing it. Incompatible with LoRA under EAGLE/NEXTN/EAGLE3.</td>
      <td>`1`</td>
    </tr>
  </tbody>
</table>

### DeepSeek-Specific NPU Optimizations

These switches optimize DeepSeek-style MLA attention and MoE layers; they are used in the DeepSeek best practices and may apply to similar architectures:

<table>
  <thead>
    <tr>
      <th>Variable</th>
      <th>Purpose</th>
      <th>Typical Usage</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`SGLANG_NPU_USE_MLAPO=1`</td>
      <td>Fuses MLA preprocessing (QKV projections, layernorms, RoPE, weight requant) into a single kernel, reducing decode and target-verify latency and memory bandwidth.</td>
      <td>Used with DeepSeek R1</td>
    </tr>
    <tr>
      <td>`SGLANG_USE_FIA_NZ=1`</td>

      <td>Used with DeepSeek R1</td>
    </tr>
    <tr>
      <td>`SGLANG_NPU_USE_MULTI_STREAM=1`</td>
      <td>Runs shared experts and routed experts concurrently on separate NPU streams, overlapping shared-expert compute with expert dispatch.</td>

    </tr>
    <tr>

      <td>As needed</td>
    </tr>

## Feature Compatibility

Use this section to check a combination before you launch it. It lists only combinations with a known, actionable constraint; absence from the table means no known conflict, not a guarantee. For per-flag support status, see the [Feature Support Matrix](/docs/hardware-platforms/ascend-npus/reference/support_features).

**Symbols:** 🟢 supported and exercised together; 🟠 supported only with the constraint in the row; ❌ do not combine.

| Feature A | Feature B | Status | Constraint |
| --- | --- | --- | --- |
| NPU Graph | TP, attention DP, EP, PD, quantization, speculative decoding, DP LM Head | 🟢 | Used together in the published DeepSeek V3.2 decode configuration. |
| Chunked Prefill | TP, attention DP, EP, context parallelism, quantization | 🟢 | Default-on for mixed serving; per-rank chunk is divided by attention DP. |
| PD Disaggregation | DP LM Head | 🟢 | Used together on DeepSeek V3.2 decode. |
| Quantization | DP LM Head | 🟢 | Used together on DeepSeek V3.2 decode (`modelslim`). |
| Attention DP | `--dp-size` greater than 1 | ❌ | Model replicas cannot be combined with attention DP; `--dp-size` greater than 1 is single-node only. |
| PD decode | Prefix cache | 🟠 | Decode forces radix caching off; enable it only with the experimental `--disaggregation-decode-enable-radix-cache`. |
| Speculative decoding | Quantized target | 🟠 | The draft inherits the target quantization by default; pass `--speculative-draft-model-quantization unquant`. |
| CP (V3.2/DSA) | Attention DP greater than 1 | ❌ | The interleave DSA path requires `DP = 1`; keep attention DP off when CP is on. |
| EPLB | `ascend_fuseep` | ❌ | EPLB requires `deepep`; there is no startup guard today, so a wrong backend can fail silently. |
| EPLB | Topology | ❌ unless `TP = EP = world size` | Migration asserts `tp_size == moe_ep_size == world_size`. |
| CUDA graph | `--cuda-graph-max-bs-decode` smaller than `attn_tp_size` | ❌ | The capture bucket list becomes empty and startup aborts; use a multiple of `attn_tp_size`. |
| `TASK_QUEUE_ENABLE=2` | NPU Graph capture | ❌ | torch_npu rejects level 2 during capture; decoding roles must use `0` or `1`. |
| `HCCL_OP_EXPANSION_MODE=AIV` | A2 + DeepEP | ❌ | Keep it unset on A2 with DeepEP; vendor docs report unknown-operator errors. |
| LoRA | `SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1` | ❌ | The speculative plan stream is incompatible with LoRA under EAGLE/NEXTN/EAGLE3. |
| PD prefill | `--load-balance-method round_robin` | 🟠 | Keep `auto`: prefill resolves to `follow_bootstrap_room`, decode to `round_robin`; an explicit round-robin on prefill loses DP-rank affinity. |
| `--disable-cuda-graph` | Decode graph | 🟠 | Deprecated and global: it disables both prefill and decode graphs. Do not use it on a decode or mixed node. |
